# 法務ドキュメント（草案）

このディレクトリは、プレミアムプランの課金を開始するために必要な法務ドキュメントの草案を置く。

**まだ公開していない。** 事業者情報（氏名・住所・電話番号）が未記入であり、
この状態で本番に出すと特定商取引法11条の表示義務を満たさない。
決済フェーズで値を埋め、フロントエンドの公開ページとして実装する。

| ファイル | 内容 | 根拠 |
| --- | --- | --- |
| `tokushoho.md` | 特定商取引法に基づく表記 | 法11条・施行規則8条 |

## 確定した前提（2026-07-23）

**この表が確定値の唯一の情報源である。** 他の3ファイルは、ここにある値を消費者向けの文言に
落としたものにすぎない。値を変えるときは必ずこの表から直し、他の3ファイルへ反映する。
公開ページとして実装するときは、価格と日数を1つの定数から差し込み、手書きの複製をなくす。

設計ドキュメント14章「未決事項」のうち、2件が決まった。

| 項目 | 決定 | 備考 |
| --- | --- | --- |
| 価格 | **月額300円（税込）** | Stripe の国内カード手数料 3.6% を引いて手取り約289円 |
| 無料トライアル | **5日間・カード登録必須・終了後に自動課金** | Stripe の `trial_period_days` を使う |
| トライアルの対象 | **初回のお申込みに限る** | 再申込みには付かない。3文書すべてに明記する |
| 初回請求の時点 | **無料お試し期間が終了するのと同一の時点** | 解約の期限は「その時点より前」。日付だけの表示では足りない |
| 更新日 | 毎月同じ日。該当日が無い月は末日 | 29〜31日申込みの場合に食い違うため明記する |
| 解約の効力 | **当該課金期間の末日** | 末日まではプレミアム機能を利用できる |
| 返金 | **原則なし。** 法令上必要な場合と、当方の責めに帰すべき事由による場合を除く | 利用規約第6条2項の日割り返金がこの例外に当たる |
| 販売主体 | **個人事業主（本人名義）** | 自宅住所と携帯番号を表記に記載する |

**MoR（Merchant of Record）とバーチャルオフィスは採らない。** 前者は手数料が上乗せされ、
後者は月額費用が売上規模に見合わない。自宅住所の公開を受け入れる判断であり、
規模が大きくなった時点でバーチャルオフィスへ移行できる（表記の住所を差し替えるだけで済む）。

残る未決事項は **free と premium の機能の線引き**。
現状は設計 3.1 のとおり「週間献立の保存上限 free=10 / premium=50」のみが決まっている。
利用規約4条とLPの記述はこれが確定してから書く。

## 公開までにやること

1. 事業者情報の実値を埋める（氏名・住所・電話番号・サポート用メールアドレス）
2. `terms.md` 第4条7項の決済失敗時の猶予期間を確定（7日を想定）
3. free / premium の線引きを確定し、利用規約とLPへ反映
4. **「アカウント設定 > プランの管理」を実装する。**
   3文書すべてがこの導線を解約方法として名指ししているが、設計10章の時点で
   アカウント画面は存在せず、カスタマーポータルも対象外である。
   **この画面が無いまま公開してはならない**（表示した解約方法が事実と異なることになる）。
5. **エンタイトルメント設計6.2の `past_due` の扱いを見直す。**
   利用規約第4条7項は猶予期間中もプレミアム機能を利用できると定めたが、
   設計の分岐表は `past_due` を即 free と判定する。
   `past_due` かつ `current_period_end` 内は premium と評価するよう直す。
6. 3ドキュメントをフロントエンドの公開ページとして実装し、フッターから常時到達可能にする
7. Stripe の審査に3ページのURLを提出する（表記ページが無いと審査に通らない）
8. `checkout-display.md` の要件を満たす確認画面を実装する
9. 4文書の記載が一致していることを最終確認する
   （価格・無料お試し期間・初回請求の時点・解約の期限・解約の効力・返金条件の6点）
10. 可能なら弁護士のスポットレビューを受ける
