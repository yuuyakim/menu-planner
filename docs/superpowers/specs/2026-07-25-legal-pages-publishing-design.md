# 法務ページの公開（特商法・利用規約・プライバシー）設計

- 日付: 2026-07-25
- 対象: `menu-planner`（献立くん）
- 状態: 設計確定・未実装
- 位置づけ: 「プレミアム決済導線」整備の**サブプロジェクト1**。前提: `docs/legal/`（草案4文書＋README「公開までにやること」）、
  `docs/superpowers/specs/2026-07-23-premium-entitlement-design.md` 12章（有料化の前提条件・法務）。

## 1. 背景と目的

サブスク課金を始めるには、`docs/legal/` の草案（特商法表記・利用規約・プライバシーポリシー）を
**フロントエンドの公開ページ**として実装し、フッターから常時到達できるようにする必要がある
（README「公開までにやること」#6）。Stripe の審査にもこの3ページの URL 提出が要る（#7）。
本サブプロジェクトはこの「法務ページの公開」だけを扱う。**決済そのもの・料金プランLP・申込確認画面・
プラン管理/解約画面は別サブプロジェクト。**

## 2. スコープ

### 対象
- 3つの公開ページ: 特商法に基づく表記 / 利用規約 / プライバシーポリシー。認証不要。
- 全ページ共通の**フッター**（3ページへのリンク）。
- **利用規約を weekly=premium に更新**（README #3。4条9項「プレミアム機能の内容」の具体化、4条7項の猶予=7日 #2）。
- **事業者情報の実値を記入**（README #1）。特商法11条の表示義務を満たす。
- 事実項目の確定: 越境移転先（Neon=シンガポール）、制定日（=公開日）、解析ツール（現状なし）。

### 対象外
- 料金プランLP、申込み最終確認画面（`checkout-display.md` の実装）、Stripe 決済、Webhook、
  カスタマーポータル/プラン管理・解約画面、past_due の扱い見直し（設計6.2）。すべて後続サブプロジェクト。
- 弁護士のスポットレビュー（#10）は運用側で実施（本設計の対象外だが推奨を明記）。

## 3. 設計判断

### 3.1 `.md` を唯一ソースにして描画する（決定・ユーザー選択）

`docs/legal/*.md` を正のまま維持し、フロントで **`react-markdown` + `remark-gfm`（表のため）** で描画する。
レビュー済みの文書を TSX に二重化しない。値・文言を変えるときは `.md`（と README の確定表）だけを直す。

- **raw import**: フロントは `docs/legal/*.md` を raw 文字列として取り込む（vite の `?raw`）。
  `.md` は frontend パッケージ外（repo ルート `docs/legal/`）にあるため、**dev サーバでは vite の
  `server.fs.allow` に repo ルート（または `docs/legal`）を追加**する必要がある。build 時はバンドルに
  インライン化されるので追加設定は不要（実装時に確認）。
- 追加依存は `react-markdown` と `remark-gfm` の2つ。最小限に留める。

### 3.2 公開ルートとフッター（決定）

- ルート: `/legal/tokushoho`・`/legal/terms`・`/legal/privacy`。**認証不要**（`RequireAuth` で包まない）。
- 共有 `Footer` を App レイアウトに追加し、全ページの下部から3ページに到達可能にする
  （現在フッターは無く、ヘッダの nav のみ）。

### 3.3 利用規約を weekly=premium に更新（決定）

- 4条9項「プレミアム機能の内容」の `〈線引き確定後に具体化する〉` を、**週間まわり一式**
  （週間献立の提案・引き直し・保存・週間の買い物リスト）が premium である旨に具体化する。
  文言は `2026-07-24-weekly-premium-retier-design.md` §4 の線引きに沿う。
- 4条7項の決済失敗の猶予期間 `〈7〉` を **7日**に確定（README #2）。
- **依存**: この記述は weekly=premium（PR #145）が前提。**法務ページの公開は #145 と揃えて main に出す**
  （単独で main に出すと、規約が本番の挙動と食い違う）。

### 3.4 事業者情報の記入（決定）

- `docs/legal/{tokushoho,terms,privacy}.md` の `〈 〉` に実値を入れる。**PII（氏名・住所・電話・メール）は
  コントローラが直接記入し、コード実装のサブエージェントには渡さない**（拡散の最小化）。
- 販売URL=`https://kondatekun.yuuyakim.com`、動作環境=Chrome/Safari/Edge 各最新版。
- 越境移転（privacy 第三者提供表）: Neon Inc.／**シンガポール**（AWS `ap-southeast-1`）、Brave Software／米国。
  解析・エラー監視ツールの表・注記は「**現状なし**」として整理（導入時に追記する旨は残す）。
- **制定日 = 公開日**。公開日はこの launch を main にマージするまで未確定なので、**マージ時に確定**する。
  それまではファイル上に「公開時に確定」であることが分かる形で置く（プレースホルダを残さない最終記入はマージ直前）。

### 3.5 値の単一ソース化は本サブプロジェクトでは行わない（決定）

README は価格・日数を1定数から差し込むことを求めるが、それはアプリが値を機械的に使う場面
（CTA・申込確認）で意味を持つ。本サブプロジェクトは静的ページのみなので、値は `.md` 内の文言が
唯一の文字ソースでよい。定数化は決済サブプロジェクトで行う（過剰実装を避ける・YAGNI）。

## 4. コンポーネント構成

- `frontend/src/features/legal/content.ts`（または各ページで直接 raw import）: `docs/legal/*.md` を raw で取り込む束ね。
- `frontend/src/features/legal/LegalPage.tsx`: raw md を受け取り `react-markdown`+`remark-gfm` で描画する共通コンポーネント（prose スタイル、`kon-*` パレット）。3ページはこれに各 md を渡す薄いラッパ。
- `frontend/src/components/Footer.tsx`: 3法務ページへのリンク。App レイアウトの末尾に常時表示。
- `app/App.tsx`: 3つの公開ルート追加＋`<Footer>` をレイアウトに組み込む。
- `frontend/vite.config.ts`: dev の `server.fs.allow` に repo ルートを追加（raw import のため。必要な場合）。

## 6. 公開前チェック（README「公開までにやること」に紐づく）

マージ＝公開の前に満たすこと（本サブプロジェクトの完了条件に含める）:
- `〈 〉` プレースホルダが**1つも残っていない**（PII・制定日を含む）。
- 特商法表記の必須項目（氏名=戸籍名・住所=番地/部屋番号まで・つながる電話・動作環境・自動更新の明記）が埋まっている。
- 利用規約9項が weekly=premium を、7項が猶予7日を反映している。
- 4文書（README確定表・特商法・規約・プライバシー）の6点（価格・無料期間・初回請求時点・解約期限・解約効力・返金）が一致。
- 解約導線「アカウント設定>プランの管理」は**別サブプロジェクトで実装**する（未実装のまま公開しないこと。特商法の解約方法表記と実装の一致が要る＝launch 全体の前提）。

> 本設計・草案は法律専門家によるものではない。課金開始前に弁護士のスポットレビュー/消費者庁ガイドラインで裏を取ること（README #10）。
